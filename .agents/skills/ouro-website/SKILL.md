# Ouro website

The site markets Ouro's family apps. Every app has a landing page at `https://ouro-apps.vercel.app/<slug>/`, which is
the app's App Store **Marketing URL** and the link to share. The owner asked never to have to point out that it is
out of date: keeping it current is this skill's job, and routine updates from verified store facts are authorized
to ship without asking.

| Thing | Where |
|---|---|
| Site repository | `/Volumes/ssd/code/app-sites` (GitHub `astrojams1/app-sites`, private). This site is `sites/ouro`; the astrojams site is `sites/astrojams`; both are built from `packages/showcase` |
| Project home (research, captures, staging) | `/Volumes/ssd/projects/ouro-apps/` |

Home is a colour stage (`packages/showcase/src/components/Stage.astro`, scroll maths in `packages/showcase/src/lib/stage.js`): pinned on wide screens, natural scrolling with large screens on phones; app pages are `packages/showcase/src/pages/[slug].astro` |

What is automatic already: a GitHub workflow runs `sync:store` every six hours, commits `store.json` changes (Vercel
deploys them, bot commits included) and opens the issue **"Ouro website needs an update"** in `astrojams1/app-sites` when Apple lists an Ouro
app the catalog neither shows nor excludes, or a live one disappears. A release therefore flips the badge on its own;
everything else (new apps, unreleased apps, copy, screenshots) needs this skill.

## Run it

Use Node 22 (`PATH=/opt/homebrew/opt/node@22/bin:$PATH` on the owner's Mac). Record the run in the shared activity
ledger as the owner's `AGENTS.md` requires: one `run_id`, `skill: "ouro-website"`, events `start`, each `action` or
`finding`, `verify`, `end`, with targets, evidence (commit, deployment id, URLs) and anything skipped. Use the helper
`/Users/astro/.codex/skills/mac-memory-maintenance/scripts/ledger.py`.

1. **Sync.** At the site repository's root: `git pull --ff-only`, `npm ci`, read its `AGENTS.md`, and check open
   issues (`gh issue list --repo astrojams1/app-sites`; this site's carry "Ouro" in the title). Preserve anyone else's uncommitted work.
2. **Refresh public status.** `npm run sync:store -w sites/ouro`. Exit 2 lists a live Ouro app the site does not know; exit 3 a
   listed app Apple no longer returns.
3. **Audit App Store Connect.** `node <skill>/scripts/audit.mjs` (`--json` for detail). It reads the App Store
   Connect key from the 1Password item named in any Ouro app's `app-release.config.json`, using the token rules in
   the owner's `AGENTS.md`; never print or log a value. It prints every record on the team with its latest version
   state, whether the site shows, excludes or misses it, the local repository, and **Actions**: new records,
   renamed apps or subtitles, released apps not yet synced, catalog apps that left the team. **Follow-ups** list
   app repositories whose `listing.marketingUrl` is not the app's page here.
4. **Decide each new record.** Add it if it is for families: parents, kids, caregivers, home life. Otherwise, or if
   it is a duplicate, placeholder or test record, add it to `excluded` with a one-line reason so no later audit asks
   again. Ask the owner only when the listing leaves it genuinely unclear. An app appears as soon as it has an App
   Store Connect record and a listing to draw from; it does not wait for review.
5. **Write or refresh the entry** from the app's own listing (its repository's store data, else App Store Connect)
   and its makers' own materials (their website, notes from the app's team), following [content](references/content.md):
   headline, pitch, audience, features, trust points, FAQ, theme, and a `spotlight` or `humanSupport` line when the
   app's story needs one. Use the makers' favourite wording verbatim when they name it; label anything still in
   development exactly as they do.
6. **Source the images** per [assets](references/assets.md): a 1024px icon, 2 to 6 real screenshots, alt text.
7. **Verify** (below), then **ship**: commit to `main` with a message naming the apps changed, push, and confirm
   the Vercel production deployment for that commit is `READY` and the live pages show the change.
8. **Close the loop.** Close the GitHub issue with a comment saying what changed. For each follow-up, set the app's
   `listing.marketingUrl` in its repository through that repository's normal branch or pull-request flow, or record
   it as the next action in its release ledger when the repository has unrelated work in progress; app-release
   sends it with that app's next `asc.mjs listing`. Never push listing changes to App Store Connect from this skill.

A design or structure change (new section, new layout, new dependency) goes on a branch with a pull request and
screenshots for the owner; content and asset updates go straight to `main` once verification passes. Anything in
`packages/showcase` changes the astrojams site too: build and look at both sites, put screenshots of both in the pull
request, and say so in the report. A difference that is only words or brand belongs in `site.copy` or `site.brand`,
not in a branch of the shared code.

## Verify

- At the repository root, `npm test` and `npm run build` (both sites) pass. `npm run check` (part of the build) fails on missing fields or images, poor
  colour contrast and App Store wording Apple forbids; fix the data, never weaken the check to pass.
- `npm run preview -w sites/ouro` and look at every changed page at 1280px and 375px wide. Sections fade in on scroll, so wait a
  second (or add `is-visible` to `.reveal` elements) before judging a blank area. On the phone width,
  `document.documentElement.scrollWidth` must equal the viewport width: no sideways scrolling.
- After any change that touches the home page (an app added, removed or reordered, new screenshots, stage code), run
  the browser scroll check: paste `packages/showcase/tests/browser/stage-scroll.js` into the home page of the preview and
  `await stageScrollCheck()` at 1440×900 and 375×812. It must return `ok: true`. A full run takes a few minutes in a
  hidden browser pane; start it without awaiting (store the promise's result on `window`) and poll, since evaluation
  tools time out.
- Every iPhone browser, Chrome included, runs WebKit, and the browser pane is Chromium. After a home-page or layout
  change, also open the preview in Mobile Safari on an iOS Simulator (the simulator reaches the Mac's `localhost`;
  follow the owner's simulator storage and lease rules) and check the stage at the phone size. The scroll check can
  run there too: serve it from the built page and show its result on screen.
- Open `sites/ouro/dist/og/<slug>.png` (the link-preview card) and check the headline, icon and status fit.
- A live app shows Apple's black badge, its rating once five people have rated it, a QR code on desktop and the
  sticky bar on phones; a coming-soon app shows "Coming soon to the App Store" and never the badge.
- After deploying: `curl -s -o /dev/null -w '%{http_code}' https://ouro-apps.vercel.app/<slug>/` is 200.

## Gotchas

- Füd's repository `store/assets/app-icon.png` is Apple's icon-grid template, not the icon. Use the App Store
  artwork (`store.json` → `artworkUrl`).
- App Store Connect build icons (`iconAssetToken`) are 120px at most. Take icons from the app repository's
  `Assets.xcassets/AppIcon.appiconset` or, once live, the App Store artwork. Moment to Meaning has no local
  repository; its icon is a vector redraw (`iconNote`) until the live 1024px artwork can replace it.
- Giraffe Stretch has three records on the team; `6828973581` (`com.ouro.giraffestretchtest1`) is the real one.
- The public lookup can trail Apple's release by hours. A released app still "coming soon" right after release
  needs only `sync:store` later, not a manual status edit.
- Link-preview cards are drawn by satori from `.woff` Latin fonts: keep their text to Latin characters, no
  emoji or ★.
- The browser preview pane can return the previous frame on the first screenshot after a scroll; take two.
- WebKit sized a stage screenshot from its own 74svh cap instead of its grid cell's `100%`, so on iPhones it ran over
  the jump dots and off the frame while Chromium looked perfect. The stage sizes screens with container query units.
- Don't pin the stage on phones. The owner's iPhone recordings showed a pinned stage feels dead under the finger,
  shrinks the screenshots and jolts as the browser toolbars come and go; phones get natural scrolling.
- iOS Safari paints the strip behind the clock one solid colour when anything fixed touches the top edge, and keeps
  that colour while the page changes. Never give the fixed header a background, move the bar, or slide chips off the
  top; hidden chips fade out in place. Check by scrolling between apps in the iOS Simulator with the chips shown.
- Satori ignores padding when sizing a fixed-height box: give a padded card `height: 630 - top - bottom`, or its last
  row falls off the preview image.
- Link only to public pages. Moment to Meaning's own site was private (HTTP 401) on 2026-11-02, so the page has no
  `links.website` yet; add it once the site is public.
- Astro 7.4 needs Node 22.22 or later; the Homebrew `node@22` is new enough, the default `node` (20) is not.
